# 混合检索对比实验报告

  ## 实验配置
  - 素材：60篇视频脚本，12个类别 × 5篇
  - 分块：SentenceSplitter(chunk_size=256, overlap=50)
  - 嵌入：paraphrase-multilingual-MiniLM-L12-v2
  - BM25：jieba 中文分词
  - 评测：5个领域query各一次(美食探店,科技评测,历史科普,学习技巧,产品发布)

  ## 结果

| Query          | 稠密向量 Top-1   | BM25 Top-1      | RRF Top-1        |
| -------------- | ---------------- | --------------- | ---------------- |
| 推荐美食店铺   | 老北京私房菜馆 ✅ | 《纳瓦尔宝典》❌ | 老北京私房菜馆 ✅ |
| iPhone 17体验  | iPhone 17评测 ✅  | iPhone 17评测 ✅ | iPhone 17评测 ✅  |
| 秦始皇统一文字 | 书同文段落 ✅     | 《纳瓦尔宝典》❌ | 书同文段落 ✅     |
| 提高学习效率   | 学编程弯路 ✅     | 《纳瓦尔宝典》❌ | 学编程弯路 ✅     |
| 智能戒指介绍   | 戒指发布会 ✅     | 《纳瓦尔宝典》❌ | 戒指发布会 ✅     |

  ## 发现

  1. **稠密向量在短文档场景下完胜BM25。**
    60篇素材每篇150-300字，词频差异不足以让BM25有效区分。稠密向量对所有5个query都能精准命中。

  2. **BM25只在"iPhone 17"这种专有名词query上有用。** 关键词精确匹配时BM25有效，但同义表达（"美食" vs "好吃的"）失效。

  3. **RRF在BM25不可靠时会引入噪音。** 4个query的RRF Top-2都是一篇无关的读书笔记。

  4. **当前最优方案：纯稠密向量检索。** 混合检索在文档短、语义查询为主的场景下不带来增益。

  ## 结论

  素材量 < 100篇、单篇 < 500字时，单用稠密向量检索即可。BM25+RRF的混合方案在文档量 > 1000
  篇或包含大量专有名词/编号的场景下才有明显价值。当前项目用稠密向量就够了。
